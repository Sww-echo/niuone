# 策略研究说明

简体中文 | [English](README_EN.md)

本文档集中说明 NiuOne 中用于研究实验的信号筛选、模拟决策和复盘机制。相关能力仅运行在本地研究与模拟环境中，不连接券商账户，不执行真实资金交易，也不构成投资建议。

## 1. 研究流程

NiuOne 将研究流程拆分为四层：

1. **候选生成**：根据当前启用的规则扫描公开行情数据，形成待观察样本。
2. **信息补充**：按需聚合指数、板块、资金、市场热度和近期消息。
3. **模拟判断**：结合规则约束、账户状态与可选模型输出，生成模拟记录。
4. **归档复盘**：保存输入摘要、来源状态、模拟操作和结果，便于后续检查。

策略输出是实验性信号，不应作为真实交易依据。行情源或模型源暂时不可用时，系统会记录来源状态，并按当前可用信息继续或跳过对应流程。

## 2. 独立策略

设置页直接选择一套当前策略，一次只激活一套。基础策略、Z 哥、李大霄、板块潮汐、牛牛战法和预设文字策略是同级、互斥的独立策略；每套策略独立提供候选范围、评分、买入、卖出、仓位和模型 Prompt。未启用策略不会进入本轮新开仓扫描或决策上下文。

切换策略不会篡改历史持仓归因。当前激活策略只控制本轮新开仓 BUY；已有持仓继续按买入时记录的 `strategy_mark` 动态加载原策略退出纪律。每轮选股及买卖流程都先刷新并检查全部已有持仓的本地退出规则，再处理当前策略候选和模型判断；即使候选为零或日内亏损预算触发，SELL/HOLD 检查仍继续运行，日内亏损预算只暂停新开仓。预设文字策略使用基础扫描结果作为原始候选池，再按文字规则独立完成模拟判断；如果文字为空，则不会产生新的模拟建仓记录，只对已有模拟持仓执行风险检查。

### 2.1 用户：如何启用与触发

1. 在设置页把“当前独立策略”设为“板块潮汐”，对应配置为 `DASHBOARD_ACTIVE_STRATEGY=sector_tide`。该设置可热应用，保存后从下一轮扫描开始生效，不需要重启 Dashboard。
2. 新候选和模型买卖复用实战页面的共享调度计划，由 Dashboard 进程内置调度器按 `DASHBOARD_PRACTICE_SCHEDULE_TIMES` 触发；板块潮汐没有另一套独立选股定时器。
3. 如需立即运行，可在实战页面点击“手动触发选股及买卖策略”。一次完整执行包含全市场扫描、候选生成、模型判断和执行层风险复核。
4. 09:25 的扫描只使用竞价结果形成候选，不会在 09:25–09:30 静默期模拟成交；可执行动作会等待 09:30 后重新检查价格、交易时段和风险限制。

调度职责分为两个进程：

| 工作 | 进程 | 主要配置 | 行为 |
|---|---|---|---|
| 选股和模型买卖 | Dashboard | `DASHBOARD_B1_SCHEDULE_ENABLED`、`DASHBOARD_PRACTICE_SCHEDULE_TIMES` | 到点或手动触发后先检查全部已有持仓的原策略退出，再把当前激活策略候选送入模拟决策；零候选仍执行持仓退出检查 |
| 本地自动退出 | Cron Scheduler | `DASHBOARD_B3_EXIT_TIME`、`DASHBOARD_TIME_EXIT_TIME` | 在配置时间刷新持仓行情并检查结构止损、退潮、时间窗、2R 和 2ATR 等规则 |

自动退出是离散时间检查，不是券商条件单或逐笔行情实时监控。页面刷新只读取状态，不会触发自动成交。切换到其他策略后，板块潮汐不再产生新候选，但已有板块潮汐持仓仍按保存的策略标记接受退出检查。

### 3.1 基础策略

- **突破确认**：平台或前高突破后回踩站稳，作为趋势确认样本。
- **趋势回踩**：强趋势标的回踩 BBI / EMA 不破，作为低位观察样本。

### 3.2 Z 哥规则组

该规则组参考 [`zettaranc-skill`](https://github.com/lululu811/zettaranc-skill) 中整理的公开方法，当前包含：

- **少妇 B1**：关注 J 值低位、N 型上移、缩量回调和 BBI 约束。
- **B2 确认**：观察 B1 后的放量阳线确认，并过滤明显滞后或偏离 BBI 过远的样本。
- **B3 中继**：观察 B2 后的小阳线或十字星，以及分歧转一致特征。
- **超级 B1**：观察放量破位后的缩量企稳，以及 J 值仍处低位的形态。

选股评分同时复用 Dashboard“资金流动”页的东方财富行业板块“今日主力净额”快照。个股所属行业进入主力净流入前十时，第 1 名增加 1.50 分，之后每降一名递减 0.15 分，第 10 名增加 0.15 分；显示分仍保持 10 分制上限，排序分保留封顶前的行业加分，因此技术分同为 10 分时仍优先行业排名更高的个股。行业标签缺失、名称无法唯一匹配、榜单为空、请求失败或只能读取过期缓存时保持原技术分，不把缺失数据当成负面信号。

退出与风险规则包括：前低或入场 K 线约束、防卖飞评分、分批退出、S1 / S2 / S3 逃顶、出货形态、白线 / BBI 破位、峰值回撤、ATR 吊灯保护，以及 B2、B3、超级 B1 的时间约束。

少妇 B1 使用“硬退出优先、软退出确认”的持仓状态机。买入后至少观察 3 个 A 股交易日，开盘前 30 分钟只允许收盘确认的结构止损、白线死叉黄线、白线连续两日破位和高置信度出货等硬退出。盈转亏、单次 BBI/评分转弱、峰值回撤、ATR 吊灯和时间效率属于软信号：行业主力净流入或下跌缩量时继续持有；普通软信号需在不同检查窗口连续出现两次才减半；行业主力净流出与预测放量下跌同时出现时可直接确认减半。缺失、失败或过期的资金流与量能数据保持中性，剩余趋势仓仍等待结构性退出。

行业方向复用每轮扫描已经取得的东方财富行业主力净额快照。个股预测量比使用实时累计成交量、近 20 个已完成交易日成交量中位数，以及 Dashboard 现有的大盘同时间成交进度/全天成交额预测推导，不新增独立行情请求。模型对少妇 B1 输出的 `SELL` 只作为建议，执行层会降级为 `HOLD`，实际卖出统一由本地持仓状态机执行。

### 3.3 李大霄规则组

该规则组参考 [`li-daxiao-skill`](https://github.com/sherjy/li-daxiao-skill) 的政策、价值、底部发育、逆向情绪和杠杆风控框架，并使用高流动性蓝筹、低位企稳、低换手、缩量低波动、反追高和风险标的过滤作为可执行代理信号。

### 3.4 板块潮汐

板块潮汐每轮先对同一批高流动性股票生成一个横截面快照，再按“市场状态 → 行业潮位 → 板块内个股强度”筛选，行业是硬门控而不是个股分数的加分项。

每轮只在滚动最新龙虎榜快照的日期精确等于扫描日前一 A 股交易日时读取，把主榜净买卖、买卖前五全部席位净额和机构席位净额作为确认因子；同日尚未完整发布的数据或更早日期快照均保持中性，不做任意日期回退。行业潮位最多调整 ±2.5 分，个股综合分最多调整 ±0.35 分，二者合计对 10 分制候选分的影响不超过 ±0.45。未上榜不视为负面，快照缺失或席位不完整时按可用主榜信息或中性值降级；若个股当日涨幅超过 7% 或距 EMA20 超过 1.5 ATR，龙虎榜正向加分会被抑制，负向风险提示仍保留。该因子用于候选排序和历史检验，不代表已经证明会提升未来胜率。

扫描同时读取仅对当日有效、且对应最近一个已完整收盘美股交易日的隔夜摘要：整体风险偏好最多调整 -0.15 至 +0.05 分，摘要中明确映射到 A 股行业的美股板块表现最多再调整 ±0.15 分。完成首轮技术与行业评分后，只对排名前五的板块潮汐候选查询最近 3 天个股重大消息，结构化为利好、利空或中性；利好调整 +0.15 分，利空调整 -0.30 分，缺失、过期或无法识别时保持中性。龙虎榜、隔夜美股和消息面三类外部确认合计限幅为 -0.90 至 +0.60 分；正向信号仅在 A 股行业本身处于领先或改善状态、且个股未触发追高条件时生效，负向风险始终保留。扫描阶段的消息记录会写入候选缓存供模型决策直接复用，避免同一轮重复请求。

- **主线领航**：进攻或轮动行情中的领先行业，个股须处行业前 20%，只做突破或 EMA20 附近缩量回踩；8% 是单票绝对上限，实际仓位由动态风险预算决定。
- **轮动初升**：行业排名和广度快速改善，个股须处行业前 30%，拒绝单日涨幅超过 7% 或距 EMA20 超过 1.5 ATR 的追高；6% 是单票绝对上限。
- **冰点修复**：仅在防守解除后的修复状态做率先转强行业，T+2 未确认退出；4% 是单票绝对上限，实际仓位由修复状态风险预算决定。

风险预算随市场状态切换。进攻、轮动、修复的单笔权益风险预算分别为 0.30%、0.20%、0.10%，策略内组合未实现止损风险上限为 1.50%、0.80%、0.30%，单行业风险上限为 0.60%、0.40%、0.20%；对应总仓上限为 45%、30%、15%，行业敞口上限为 12%、10%、6%，防守状态全部归零并禁止新仓。同一行业最多 2 只。有效损失距离按“结构止损距离 + max(近 60 日向下跳空 P95，0.5 ATR 占比) + 0.20% 费用滑点”计算，实际单票上限取风险预算反推仓位与注册绝对上限 8%/6%/4% 的较小值。行业分数连续两个交易日低于 55、市场复合风险硬停止且行业转弱、或策略时间窗未兑现时退出；盈利达到 2R 先减半，余仓使用 2 ATR 跟踪。行业资金流缺失时使用量能参与度作为明确标记的后备指标，不会把缺失值当作净流入。

#### 用户：仓位和退出如何执行

- 模型必须为每条 BUY/SELL 给出 100 股整数倍数量。执行层不会替模型补默认仓位，也不会把超额订单自动缩小后成交。
- 候选必须有有效结构止损，结构距离须同时不超过 6% 和 1.5 ATR；缺少历史跳空/ATR 缓冲时禁止买入。
- 实际买入数量会依次接受单票动态上限、市场总仓、同行业数量、行业敞口、单笔风险、策略组合风险和策略内行业风险检查，任何一项超限都整笔拒绝，并在决策日志中记录原因。
- 市场状态预算是板块潮汐的最高许可值；全局盘面指引、`DASHBOARD_MAX_TOTAL_POSITION_PCT` 或现金缓冲更严格时，执行层取其中最小值，不会因全局配置更宽松而放大板块潮汐预算。
- 总仓和行业敞口按整个模拟账户计算；同行业数量会计入账户中所有带同一行业标签的持仓。组合止损风险和行业止损风险只汇总板块潮汐策略持仓。
- 主线领航 5 个交易日未兑现、轮动初升 3 个交易日不延续、冰点修复 T+2 未确认，均在尾盘时间检查中退出。
- `2R目标 = 平均成本 + 2 ×（平均成本 - 入场结构止损）`。首次达到 2R 减半，余仓在跟踪线高于成本后按 `持仓最高价 - 2 × ATR` 退出。

#### 开发者：状态、评分和数据契约

市场状态由同一轮扫描快照生成。市场综合分使用核心指数趋势 25%、涨跌家数广度 25%、中位涨跌幅 15%、涨跌停结构 15%、样本 20 日趋势 10% 和量能参与度 10%。状态机口径如下：

| 状态 | 判定 |
|---|---|
| `offensive` | 市场分数 ≥65 且上涨广度 ≥55%，并通过状态确认 |
| `rotation` | 未触发防守且不满足进攻条件，并通过状态确认 |
| `recovery` | 上一确认状态为防守，本轮原始状态已经解除防守 |
| `defensive` | 复合硬停止，或市场分数 <40；风险预算归零 |

复合硬停止要求指数破位、市场广度破位和跌停扩散同时成立。除硬停止外，状态变化通常需要连续两轮出现同一原始状态；首次没有历史状态时直接采用本轮结果。

行业评分权重及潮位阈值：

| 因子 | 权重 |
|---|---:|
| 20 日相对强度分位 | 25% |
| 5 日相对强度分位 | 15% |
| 排名加速度分位 | 15% |
| EMA20 以上广度 | 20% |
| 20 日新高占比 | 10% |
| 行业资金流；缺失时使用量能参与度 | 10% |
| 行业成交额流动性分位 | 5% |
| 前一交易日龙虎榜确认 | 基础分之外限幅 ±2.5 分 |
| 最近已收盘美股盘面与行业映射 | 个股综合分之外限幅 -0.25 至 +0.20 分 |
| 前五候选最近 3 天个股消息面 | 个股综合分之外利好 +0.15、利空 -0.30 分 |

行业至少需要 3 个有效成员，个股至少需要 55 根日 K。`leading` 要求行业分数 ≥75 且 20 日相对强度分位 ≥70；`improving` 要求分数 ≥65、排名加速度 ≥15 且 5 日相对强度分位 ≥65；分数 <45 或 20 日相对强度分位 <35 为 `lagging`，其余为 `weakening`。

主线领航、轮动初升、冰点修复的入选评分阈值分别为 8.0、8.2、8.5；板块内强度分位分别至少为 80、70、70。扫描结果必须把 `market_regime`、行业潮位、龙虎榜快照日期/可用性/限幅调整、隔夜美股交易日/风险偏好/行业映射、消息面标签/摘要/抓取时间、结构止损、跳空缓冲、有效损失距离和各级风险预算随候选写入缓存，执行层会用实时成交价和共享风险参数重新计算，不信任模型自行给出的风险数值。

核心实现位于 `app/strategies/scoring/sector_tide.py`、`app/strategies/sector_tide_risk.py` 和 `app/trading/practice_trader.py`。专项回归入口为 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_sector_tide_strategy.py' -v`，全量验证入口为 `./scripts/validate.sh`。

### 3.5 牛牛战法

牛牛战法先在同一轮全量有效行情横截面中为每只股票计算强势分，再按行业聚合为可审计的“主题代理”。强势分综合 20 日与 5 日相对强度、量能参与、成交额相对分位、EMA20/EMA50 趋势和 20 日新高。成交额仅表示资金参与度，不是流动性准入条件，也不参与仓位上限计算。行业只是当前稳定的数据代理，不把名称相近的股票自动归为同一概念；后续接入可靠概念标签时可替换映射层，不改变状态和风控合同。

主题分由强股强度、强股广度、领涨梯队、资金参与、跨市场日期持续性和龙虎榜/消息确认构成。按强股强度与成交额生成贡献权重，并用有效强股数 `1 / Σ(weight²)` 与最大单股权重识别集中度；单只股票独强会受到惩罚，不能确认市场主线。题材强度页面另外展示归一化的“有效广度”，计算为 `有效强股数 / 题材有效样本数 × 100%`，便于不同规模题材横向比较；原始有效强股数仍用于状态阈值。系统允许输出 `mainline.mode=none`，不会为满足交易频率强行选出主线。

主题状态按 `candidate → emerging → mainline → diverging → fading/inactive` 迁移，但“扫描确认”与“交易确认”已分离：同一交易日无论扫描多少次，达到主线横截面标准也只记录为 `intraday_mainline` 日内观察，不直接授权买入。只有相邻交易日仍达到强势主题标准，并且前 5 只核心强股中至少 2 只延续，才确认 `mainline`；日期断档或核心股全部更换都会重置确认。确认主线要求主题分 ≥75、至少 3 只强股且有效强股数 ≥2.4；启动主题要求分数 ≥65、至少 2 只强股且有效强股数 ≥1.7。已确认主线转弱时先进入分歧或退潮状态，避免单次噪声直接改写持仓。

- **牛牛反转试仓**：不降低原有启动或主线门槛，而是在题材前期偏弱后出现V形修复时启用独立早期路径。有效报价覆盖需 ≥70%，上涨广度 ≥60%，涨幅中位数 ≥0.5%，低点反弹中位数 ≥1.5%，且至少 2 只股票涨幅 ≥1.5%；资金数据可用时还必须为净流入、由负转正或明显改善。上述条件须在同一交易日完成两次、且间隔至少 20 分钟的确认；个股只接受日内强度前三、涨幅与低点反弹均 ≥1.5%且已收复昨收。阈值 7.6，单票绝对上限 5%，T+0 禁止加仓。
- **牛牛领航**：仅做进攻/轮动行情中已完成跨交易日确认的 `mainline`，个股必须是主线前 20% 的核心强股，只接受有效突破或首次 EMA20 缩量回踩；进攻行情的追高硬上限放宽为单日涨幅 7%/距 EMA20 1.5 ATR，轮动行情为 5%/1.25 ATR，超过原 4%/1 ATR 的买点保留风险提示；阈值 8.0，单票绝对上限 30%。
- **牛牛回踩**：主题仍为 `mainline/diverging` 且分数 ≥70，个股处前 30%，只接受 EMA20 承接或重新收复；进攻行情的追高硬上限为单日涨幅 5%/距 EMA20 1.25 ATR，轮动和修复行情仍为 4%/1 ATR；阈值 8.2，上限 25%。
- **牛牛启动**：主题处 `emerging`、已跨相邻交易日延续且至少两只核心强股保持连续，核心股突破或收复后只建观察仓；纯日内强势不得触发；单日涨幅 >7% 或距 EMA20 >1.5 ATR 不追；阈值 8.4，上限 15%，升级主线前不得加仓。

成熟路径在进攻、轮动、修复状态的单笔权益风险预算分别为 1.50%、1.00%、0.60%；反转试仓收紧为 0.35%、0.30%、0.25%。策略内组合风险上限仍为 4.50%、3.00%、1.80%，反转路径的单主题风险上限为 0.70%、0.60%、0.50%，题材敞口上限为 12%、10%、8%；总仓上限仍为 70%、55%、35%，防守状态全部归零。同一主题最多 2 只；策略同时持仓硬上限为 5 只，盘面与午盘前动态限制通常会进一步收紧到 3 只。反转试仓以当日V形低点为结构止损，距离硬上限为 4%/1.2 ATR；成熟路径继续按进攻 10%/2.5 ATR、轮动 8%/2 ATR、修复 6%/1.5 ATR 复核。牛牛战法使用 14 日真实波幅简单均值，并在候选与持仓中显式记录 `atr_period=14`；历史字段 `atr20` 仅作为兼容别名保留。有效损失距离包含结构止损、跳空缓冲和 0.20% 执行缓冲，实际仓位由风险预算反推。

龙虎榜和前五候选最近 3 天消息只作限幅确认：正向信息在追高时被抑制，不能把弱主题或无买点股票变为可买；明确利空仍降权。反转试仓只有在下一交易日继续满足跨日启动条件时才能升级为牛牛启动，完成主线确认后才能升级为领航或回踩；T+1 未延续即退出，T+2 仍未升级则强制退出。成熟路径继续按结构止损、主题连续转弱、市场硬停止叠加退潮、领航 5 日/回踩 3 日/启动 T+2 未兑现、2R 减半和 2 ATR 跟踪退出。核心实现位于 `app/strategies/scoring/niuone.py`、`app/strategies/niuone_risk.py` 和 `app/trading/practice_trader.py`。专项回归入口为 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_niuone_strategy.py' -v`，全量验证入口为 `./scripts/validate.sh`。

Dashboard 的“题材强度”栏目（`/niuone-mainline`）是独立于交易范围和当前交易策略的全市场题材研究页，展示市场状态、跨日确认主线、V形反转试仓、日内观察题材、强度最高的 5 个题材及核心股延续。覆盖率按“有效进入题材聚类的股票数 / 全量参考池股票数”计算，不读取设置中的选股范围，也不展示交易候选、仓位或买入状态。未覆盖股票按互斥处理阶段标记为 K 线不可用或少于 30 根、历史不足 55 根、关键指标无效、行业映射缺失或其他数据不完整；旧快照没有原因明细时会明确等待下一次扫描补齐。Dashboard 默认在交易日 09:10 运行 `--prewarm-kline-cache`，把全量非 ST 股票最近 120 根前复权日 K 保存到私有 SQLite；盘中用批量实时行情追加或替换当天 K 线，仅对缓存缺失或日期过期的股票回源。市场情绪后台默认每 30 秒取得一份通过覆盖校验的腾讯逐股最新报价；题材快速计算器复用同一份报价，在进程内读取日 K 和行业本地缓存、沿用最近完整研究扫描的慢速确认分量，并独立写入 `niuone_mainline_minute_latest.json`。它不会额外请求腾讯、新闻模型或交易接口，覆盖不足或报价过期时也不会覆盖上一份有效结果。采样间隔可通过 `DASHBOARD_MARKET_BREADTH_SAMPLE_INTERVAL_SECONDS` 在 30～600 秒之间配置。每轮共享定时或手动交易扫描结束后，Dashboard 仍会在后台另启 `--niuone-mainline-only` 完整研究扫描；它固定使用牛牛题材算法和全量非 ST 参考池，只原子更新专用 `niuone_mainline_latest.json`，不会改变当前策略、候选缓存或模拟买卖。页面从分钟快照、完整研究快照和迁移期缓存中选择生成时间最新的一份。题材数量限制仅用于公开页面，专用缓存仍保留全部题材供跨日连续性判断。浏览器只能读取字段白名单生成的公开读模型，不直接访问逐股行情、原始扫描上下文或本地 SQLite。

上述名称仅用于标记项目中的规则实验，不代表相关原作者参与、认可或背书本项目。二次分发相关说明时，请保留对 `zettaranc-skill` 与 `li-daxiao-skill` 的引用。

## 4. 模拟决策情报包

模拟流程可以将多个来源压缩为一个结构化上下文，并随决策日志保存。默认可能包含：

- 盘面监控指引和隔夜市场摘要；
- A 股指数、A50、美股指数或期货、黄金和原油等行情；
- 板块涨跌、行业资金、成交热度与换手信息；
- 候选样本的近期消息，以及行业与市场数据的共振或背离；
- 模拟账户现金、总仓位、持仓比例、盈亏状态和规则标记。

每次实战选股会复用扫描器在当前选股范围内已经取得的实时报价，按当时的上涨/下跌家数和涨跌停广度重算盘面标签；数据覆盖率不足、快照过期或仍处于 9:25 竞价阶段时，回退到最近的竞价、午盘或盘后报告。即使本轮没有候选股，也会刷新并记录盘面上下文。

仓位比例按 `价格 × 数量 ÷ 当前模拟总权益` 计算。日志会记录单次变化占模拟总权益的比例，以及变化后的单项和总仓位比例。

相关配置：

| 配置项 | 说明 |
|---|---|
| `DASHBOARD_DECISION_INTELLIGENCE_ENABLED` | 是否启用结构化情报包 |
| `DASHBOARD_DECISION_INTELLIGENCE_TTL_SECONDS` | 聚合数据缓存时间 |
| `DASHBOARD_DECISION_INTELLIGENCE_MAX_ITEMS` | 各类信息的最大条目数 |
| `DASHBOARD_TRADE_DISCIPLINE_TEXT` | 自定义模拟纪律文本 |
| `DASHBOARD_MAX_OPEN_POSITIONS` | 最大模拟持仓数量参考 |
| `DASHBOARD_MAX_NEW_BUYS_PER_DECISION` | 单轮新增模拟样本数量参考 |
| `DASHBOARD_MAX_SINGLE_POSITION_PCT` | 单项模拟仓位比例参考 |
| `DASHBOARD_MAX_TOTAL_POSITION_PCT` | 总模拟仓位比例参考 |
| `DASHBOARD_MIN_CASH_RESERVE_PCT` | 模拟现金保留比例参考 |

百分比配置默认主要用于模型上下文和研究纪律；带注册硬限制的策略会在模拟执行层复核其自身限制。牛牛战法的单票上限由独立风险预算和 30%/25%/15%/5% 注册上限决定，不会被默认 10% 单票参考值压回；全局总仓、动态盘面总仓和现金保留限制仍与策略上限取更严格者执行。无论是否硬拦截，这些设置都不应被视为真实交易账户的风险保障。

## 5. 配置方式

优先在 dashboard 设置页维护当前独立策略、文字规则和模拟纪律。每轮只启用一套策略；基础策略、Z哥、李大霄、板块潮汐、牛牛战法和后续新增策略的候选、买入、卖出、仓位与 Prompt 规则互不混用。对应环境变量包括：

| 配置项 | 说明 |
|---|---|
| `DASHBOARD_ACTIVE_STRATEGY` | 当前独立策略：`base`、`zettaranc`、`li_daxiao_bottom`、`sector_tide`、`niuone` 或 `preset_text` |
| `DASHBOARD_PRESET_STRATEGY_TEXT` | 自定义预设文字规则 |
| `DASHBOARD_STOCK_UNIVERSE` | 最终候选和新买入范围，多选值为 `st`、`chi_next`、`star_market`、`main_board`；默认仅主板；牛牛的全量参考池不会扩大该交易范围 |
| `DASHBOARD_TRADE_DISCIPLINE_TEXT` | 额外模拟纪律 |

启用牛牛战法时，扫描器会把当前系统支持的沪深非 ST A 股全量范围（主板、创业板、科创板）作为市场与主线参考池：全量获取实时行情，并让参考池中的每只股票进入不设数量上限的 K 线深度分析，不再按成交额、当日涨幅或涨停幅度做前置过滤。最终展示候选和新买入仍严格受 `DASHBOARD_STOCK_UNIVERSE` 限制，并只要求存在可用于模拟成交的有效价格；已有持仓即使后来超出设置范围，仍允许执行止损、止盈和其他卖出风控，避免切换范围后无法退出。ST 仅在设置显式选择时才可进入最终交易范围。北交所尚未接入当前行情、板块涨跌幅和交易权限模型，因此不在参考池内。

旧版 `DASHBOARD_STRATEGY_SOURCE` 与 `DASHBOARD_ENABLED_PERSONA_STRATEGIES` 仅用于无缝读取历史配置；新设置保存后以 `DASHBOARD_ACTIVE_STRATEGY` 为准。

本地配置默认保存在 `.local-data/dashboard.env`。该文件可能同时包含模型密钥和管理凭据，不应提交到 Git 或复制到公开上下文。

## 6. 扩展独立策略

策略代码统一放在 `app/strategies/`：

- `registry.py`：策略元数据、分组、别名、启停和设置项；
- `scoring/`：指标、硬过滤、各策略评分器及多策略比较引擎；
- `selection.py`、`policy.py`：候选准入、展示筛选与仓位策略；
- `attribution.py`、`performance.py`：策略标记、归因和绩效汇总；
- `exits.py`、`prompts.py`：策略专属退出规则和模型提示词片段。

`app/screening/multi_strategy.py` 负责行情获取、全市场扫描和缓存编排，`app/trading/practice_trader.py` 负责账户、风控和模拟成交编排。旧模块名适配器集中在 `app/compat/`，新代码应从 `strategies` 包导入。

新增内置策略时：

1. 在 `app/strategies/registry.py` 增加 `label`、`color`、`desc`、`scorer`、`profile`、`position_limit_pct` 和 `aliases`；
2. 在 `app/strategies/scoring/` 的对应文件中实现 `score_xxx(rows)`，并在 `scoring/__init__.py` 的显式映射中注册；
3. 如有专属退出或决策语义，只修改 `exits.py` 或 `prompts.py`，无需把规则写回扫描器或交易器；
4. 为评分边界、空数据和异常行情补充自动化测试；
5. 运行 `./scripts/validate.sh` 完成验证。

扫描器会遍历当前启用策略的 scorer，并将 `strategy_meta` 输出给 dashboard 与模拟复盘模块。

## 7. 使用边界

- 不要将模型生成内容视为事实，应回查原始数据和信息来源。
- 不要使用本项目替代持牌机构服务、专业风险评估或个人独立判断。
- 历史回放、规则评分和模拟结果不代表未来表现。
- 扩展数据源时，应确认数据授权、调用频率、隐私和再分发要求。
